MBR Decoding Explained

2025-03-15 Minimum Bayes Risk Language model inference

Companion note to Theoretical Guarantees for Minimum Bayes Risk Decoding .

Minimum Bayes Risk (MBR) decoding replaces the single highest-probability candidate with the candidate that performs best under an expected utility criterion. In simpler terms, it asks which output still looks good when compared against a set of alternatives.

The core idea

Given candidate outputs y_1, ..., y_n, MBR chooses the one with the largest average utility against a reference set. A rough implementation looks like this: 

def mbr_decode(candidates, utility):
    best_score = float("-inf")
    best_candidate = None

    for candidate in candidates:
        score = 0.0
        for reference in candidates:
            score += utility(candidate, reference)

        if score > best_score:
            best_score = score
            best_candidate = candidate

    return best_candidate

The real decisions are hidden in candidates and utility. Candidate quality depends on how you sample, while the utility function encodes what "good" means. BLEU-style overlap, model-based metrics, and learned judges all lead to very different behaviors.

Why it matters

MBR often works well because it rewards candidates that are centrally located with respect to the candidate set. This is especially helpful when the highest-probability sample is brittle, overly generic, or locally attractive but globally poor.

  • It can reduce unlucky single-sample failures at inference time.
  • It makes test-time compute explicit instead of hiding it inside larger models.
  • It gives a clean lens on how utility design shapes final outputs.

Where the cost comes from

The downside is computation. If you compare every candidate against every other candidate, the cost grows quadratically with the set size. In practice, you often need to balance three knobs:

  1. The number of candidates you draw.
  2. The quality and cost of the utility metric.
  3. The latency budget you can tolerate at deployment time.

This is exactly why theoretical analysis matters. It tells us whether increasing the candidate pool is buying real improvement or just burning more inference budget.

A useful mental model

I like to think of MBR as turning inference into a committee decision. MAP decoding picks the most likely speaker. MBR asks the entire room which candidate best agrees with the collective structure induced by the utility function.
